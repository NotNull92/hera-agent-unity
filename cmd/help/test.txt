Usage: hera-agent-unity test [list|cancel] [options]

Run Unity tests via the Test Runner API, or enumerate them without running.

Subcommands:
  (none)                        Run the selected tests and wait for results
  list                          List the tests that exist; runs nothing
  cancel                        End the active run and release its pending lock

Options:
  --mode <EditMode|PlayMode>    Test mode (default: EditMode)
  --filter <name>               Run: NUnit test/group name — must be a full path
                                (e.g. MyNamespace.MyClass). List: case-insensitive
                                substring matched against each full test name.
  --category <a,b>              Comma-separated NUnit [Category] names
  --assembly <a,b>              Comma-separated test assembly names (no .dll)
  --limit <n>                   list only: maximum tests returned (default 200)
  --format <json|junit|nunit>   Result format (default json); also works with resume
  --output <path>              Write the result artifact to a file (default stdout)
  --shard-index <n>            One-based shard index; requires --shard-count
  --shard-count <n>            Number of contiguous partitions; requires --shard-index
  --resume <run_id>             Keep waiting for an existing test run without
                                starting the tests again

--filter, --category, and --assembly intersect. A run narrowed by any of them
that matches nothing returns NO_TESTS_MATCHED instead of reporting a pass — a
selector typo is not a green build. Run `test list` first to see the exact full
names, assemblies, and categories that exist, then copy one back into --filter.

Without a selector, `test list` reports per-assembly and per-category counts
rather than every name, so a large project cannot flood the response.

Both EditMode and PlayMode tests start asynchronously. Their final results are
written to ~/.hera-agent-unity/status/test-results-<port>-<run_id>.json; the CLI polls
that file until completion (domain reload safe). There is no --wait flag.
If the wait reaches the global --timeout while the Connector's pending record
still exists, the CLI returns code TEST_RUN_PENDING. This means the result is
late, not that the Editor is unresponsive. Resume that exact run with a longer
timeout; this does not send run_tests again:
  hera-agent-unity --port <port> test --resume <run_id> --timeout 300000

`test cancel` asks the test framework to stop the run and always clears the
pending record, which is what releases TEST_RUN_ALREADY_RUNNING.

For an older connector response without run_id, the CLI falls back to
test-results-<port>.json. Current connectors also write that legacy file for
older PlayMode clients. Current CLIs send async_results=true; without it,
EditMode keeps its legacy synchronous response for older clients.

Requires the Unity Test Framework package (com.unity.test-framework).

Examples:
  hera-agent-unity test
  hera-agent-unity test --mode PlayMode
  hera-agent-unity test list
  hera-agent-unity test list --mode EditMode --category Smoke
  hera-agent-unity test --category Smoke
  hera-agent-unity test --assembly MyGame.Tests
  hera-agent-unity test --filter MyNamespace.MyTests
  hera-agent-unity test cancel
  hera-agent-unity --port 8094 test --resume <run_id> --timeout 300000


Artifacts and shards:
  hera-agent-unity test --format junit --output results.xml
  hera-agent-unity test --format nunit --output results.xml
  hera-agent-unity test --shard-count 4 --shard-index 2 --format junit --output shard-2.xml

Results include cases (full_name, status, duration_ms, and failure message/stack).
Existing total/passed/failed/skipped/failures/passes fields remain available.
XML sorts cases by full name and preserves a failing command exit code. Pending,
interrupted, and selector errors remain JSON errors, without a misleading XML
artifact. Output overwrites the named file; its parent directory must exist.
Older connectors provide summary-only XML: durations are omitted, failure names
may be ambiguous, and skipped names use explicit placeholders. A warning goes
to stderr. Resume without --mode labels the XML suite "Unity tests".

Shards sort selected full names using ordinal order, then divide into contiguous
balanced ranges (the first remainder shards get one extra test). Both values
must be positive Int32 integers and index must not exceed count. A shard with no
tests returns NO_TESTS_MATCHED with shard {index,count,selected:0}; it is not a pass.
Duplicate full names return AMBIGUOUS_TEST_NAMES instead of overlapping shards.
Run and shard --filter require both an exact match and a regex match against
self/ancestor suite full names. A parameterized method name selects its cases;
a case name containing regex metacharacters can match nothing. List --filter
remains a case-insensitive substring. Run categories are case-sensitive regexes
(including inherited categories and Uncategorized); assemblies are case-insensitive
exact names. List categories remain case-insensitive exact names. These selectors
intersect. Shards reject ! exclusions, invalid regexes, and regex timeouts with
INVALID_ARGUMENT. Names containing commas stay one testNames array element.
Results echo shard {index,count,selected}. Resume cannot change the saved shard.
