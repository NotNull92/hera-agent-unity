Input QA:
  hera-agent-unity input <action> [flags]

  input state                         Report EventSystem/raycaster availability
  input state --backend inputsystem   Report optional Input System devices/state
  input inspect --path /Canvas/Button Raycast target point and report blockers
  input click --path /Canvas/Button   Drive pointer enter/down/up/click through EventSystem
  input pointer_down --path /Canvas/Button
                                      Drive pointer enter/down
  input pointer_up --path /Canvas/Button
                                      Drive pointer up
  input submit --path /Canvas/Button  Select target and execute submit
  input scroll --path /Canvas/List --scroll_delta 0,-3
                                      Execute scroll handler
  input drag --path /Canvas/Handle --to_normalized 0.8,0.5
                                      Execute begin/drag/end handlers
  input keyboard --key space          Press and release an Input System key
  input keyboard --key a --mode down  Hold a key until a matching mode=up call
  input mouse --mode move --position 640,360
                                      Move the Input System mouse
  input mouse --mode click --button left --position 640,360
                                      Click and release an Input System button
  input mouse --mode delta --delta 12,-4
                                      Set mouse delta for the current update
  input mouse --mode scroll --scroll_delta 0,3
                                      Set Input System scroll delta
  call input --json '{"action":"sequence","steps":[...]}'
                                      Run bounded keyboard/mouse steps in one request
  call input --json '{"action":"record","mode":"start"}'
                                      Record bounded Input System state changes
  call input --json '{"action":"replay","path":"Library/HeraAgent/Recordings/input.json"}'
                                      Replay a hera.input-recording/1 file

  Target:
    --path </Canvas/Button>           Target by hierarchy path
    --instance_id <N>                 Target by Unity instance/entity id
    --target <path|id>                Convenience target selector

  Point:
    --position x,y                    Screen point in Unity bottom-left coordinates
    --normalized x,y                  Point inside target rect (0..1)
    --offset x,y                      Offset from target rect center in UI pixels
    --to_position x,y                 Drag end screen point (alias: --to)
    --to_normalized x,y               Drag end point inside target rect

  Options:
    --backend eventsystem|inputsystem|auto
                                      EventSystem is the default for UI actions;
                                      keyboard/mouse default to Input System
    --button left|right|middle        Pointer button (default: left)
    --click_count <N>                 Click count 1..3 (default: 1)
    --scroll_delta x,y                Scroll delta (default: 0,-1; alias: --delta)
    --steps <N>                       Drag move steps 1..120 (default: 8)
    --hold_ms <N>                     Down/up delay in ms 0..5000 (default: 50)
    --settle_frames <N>               Editor updates to wait after click 0..120 (default: 1)
    --max_results <N>                 Diagnostic entries 1..100 (default: 50)
    --strict true|false               Fail when blocked/not reached (default: true)
    --details true                    Return full raycast/handler diagnostics

  Input System options (Play Mode only):
    --key <InputSystem Key>           Keyboard key enum name (required)
    --mode press|down|up              Keyboard mode (default: press)
    --mode move|click|down|up|delta|scroll
                                      Mouse mode (default: click)
    --position x,y                    Absolute mouse screen position
    --delta x,y                       Mouse delta
    --scroll_delta x,y                Mouse scroll delta
    --button left|right|middle        Mouse button (default: left)
    --hold_ms <N>                     Press/click hold 0..5000 ms (default: 50)
    --settle_frames <N>               Updates after the final event 0..120

  Sequence contract (strict call input JSON only):
    steps                             1..32 keyboard/mouse objects
    aggregate hold                    At most 30000 ms
    aggregate awaited frames          At most 600
    wall-clock deadline               45 seconds
    ownership                         Rejects pre-held controls; cleans sequence holds

  Recording contract (strict call input JSON only):
    record mode                       start|stop|status
    record path                       New .json under project/temp; unique default
    replay path                       Existing hera.input-recording/1 .json
    bounds                            256 events, 600 frames, 30 seconds, 512 KiB
    cleanup                           Replay uses sequence-owned cleanup

  Examples:
    input state
    input inspect --path /Canvas/StartButton --details true
    input click --path /Canvas/StartButton --settle_frames 2
    input submit --path /Canvas/StartButton
    input scroll --path /Canvas/ScrollRect --scroll_delta 0,-3
    input drag --path /Canvas/Slider/Handle --to_normalized 0.8,0.5
    input state --backend inputsystem
    input keyboard --key space --mode press
    input mouse --mode click --button left --position 640,360
    call input --json '{"action":"sequence","steps":[{"action":"keyboard","key":"space","mode":"press"}]}'
    call input --json '{"action":"record","mode":"start"}'
    call input --json '{"action":"record","mode":"stop"}'
    call input --json '{"action":"replay","path":"Library/HeraAgent/Recordings/input.json"}'

  Windows Git Bash:
    MSYS rewrites arguments that begin with "/" as filesystem paths. Prefix
    hierarchy-path commands with MSYS_NO_PATHCONV=1 so /Canvas/... reaches
    Unity unchanged:
      MSYS_NO_PATHCONV=1 hera-agent-unity input inspect --path /Canvas/StartButton

  Evidence:
    EventSystem actions verify EventSystem.RaycastAll plus ExecuteEvents pointer
    handlers. Input System actions verify synthesized gameplay device state.
    Neither backend is physical OS click QA. If Computer Use cannot acquire Unity
    screenshot state, physical coordinate-click QA can still be BLOCKED while a
    Unity-level input command PASSes.
